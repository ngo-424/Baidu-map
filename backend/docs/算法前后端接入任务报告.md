## 3. 已实现的算法与接入能力

### 算法复用与进度

复用 `life-circle-algorithm`，没有复制算法实现到后端，也未改变评分、采样顺序或几何判定规则：

- 显式 BD09LL、六位小数归一化、局部米制转换。
- 145 个初始化位置、144 次外部采样查询，400→50 米四叉树细分。
- 共享点、任务内缓存、在途去重、原子预算、确定性批次及 10% 探索额度。
- 边界主动补测、范围扩展、未知支持区裁剪、孔洞与多分量保留。
- 最大两次尝试、并发 2、单次超时 8 秒、任务截止 600 秒、随机种子 `20260911`。
- 百度步行适配器继续使用 `steps_info=1`、秒数归一化、多路线选择及实际分段端点偏移检查。

`compute_isochrone(..., on_progress=None)` 新增可选同步回调。回调接收不可变 `ProgressSnapshot`，包含阶段、Provider 调用数、网络调用数、预算及耗时。原有调用兼容；回调应快速返回且不抛异常。

阶段包括初始化、扩展范围、探索、边界细化、几何重建和完成。几何重建改为 `asyncio.to_thread`，让后端状态和取消接口可继续响应。线程本身不能强制中断，任务取消后丢弃其结果，不改写终态。

### 后端任务服务

在原 FastAPI 应用上增加单进程内存任务管理：同时运行一个任务，忙时返回 409；不隐式排队。终态记录保留 30 分钟、最多 20 条，访问和任务完成时清理，服务重启后不恢复。

任务状态为 `running / cancelling / completed / cancelled / failed`。同一客户端请求标识、同一归一化中心和预算返回原任务；同标识用于不同参数返回 409。幂等性仅覆盖记录保留期。

取消使用算法 CancelToken，停止后续调度；完成后再取消不会覆盖结果。应用退出时取消任务并关闭客户端。HTTP 客户端禁用环境代理继承和重定向，沿用请求日志脱敏策略，不返回凭据或原始传输异常。

真实 Provider 要求后端 AK 和显式 QPS；服务共享限流器覆盖跨任务请求及重试，算法自身预算和限流仍生效。QPS 无法支持在默认截止内完成初始化时，创建前返回配置错误。离线模式固定使用匀速平面；复杂测试场景仅在测试应用中注入。

### 前端与地图

- 默认 `api` 入口，独立使用后端任务控制器；原 `demo` 入口及设施报告保留。
- 预算支持 200/400/800，默认 400；请求固定为 900 秒 BD09LL 分析。
- 每秒轮询任务，展示实际阶段、调用计数、数据来源和耗时，不使用模拟百分比。
- 支持取消和网络恢复；提交响应丢失后重试沿用请求标识。切换中心或预算后清空旧结果并取消旧任务；迟到的创建响应拿到 ID 后也会取消。
- 对迟到状态和结果进行版本校验；取消未获确认时提示错误，并保留再次取消的能力；过期任务可重新创建。
- Polygon 每个分量独立绘制，将外环和全部内环作为一组路径传入，保留镂空结构。依据 [百度 Polygon 镂空面文档](https://lbsyun.baidu.com/docs/jsapi?title=jspopularGL/guide/loukongPolygon)，不经过演示坐标转换。
- 可达区、未知区、不确定区、计算范围分别设置图层开关；显示质量、停止原因和范围截断警告。
- `null` 显示证据不足，空 MultiPolygon 显示有效支持范围内可达区域为空；未知不解释为不可达。
- 设施区明确显示“尚未接入”，不展示模拟数量、覆盖率或设施盲区结论。
- 地图缺配置或加载失败时，保留坐标输入和结果摘要，不回退模拟圈线。浏览器地图 AK 与后端步行 AK 分开。

## 4. 接口契约

### 创建任务

`POST /api/analyses`，成功或幂等复用返回 HTTP 202：

```json
{
  "center": { "lng": 116.404, "lat": 39.915 },
  "coordinateSystem": "bd09ll",
  "budget": 400,
  "clientRequestId": "experiment-run-001"
}
```

经纬度必须为有限数值，经度在 −180～180，纬度严格位于 −85～85；预算只接受整数 200/400/800。请求标识限 1～100 个英文字母、数字、下划线或短横线，不接收额外字段。

### 状态、结果和取消

| 接口 | 成功响应 |
| --- | --- |
| `GET /api/analyses/{taskId}` | `taskId/status/stage/requests/networkRequests/budget/elapsedSeconds/dataSource/error` |
| `GET /api/analyses/{taskId}/result` | `taskId/dataSource/center/generatedAt/facilitiesStatus/isochrone` |
| `POST /api/analyses/{taskId}/cancel` | HTTP 202，返回当前任务状态；可重复调用 |

`generatedAt` 为 Unix 秒数。`dataSource` 为 `synthetic` 或 `baidu_walking`，`facilitiesStatus` 固定为 `not_integrated`。

`isochrone` 直接保留算法业务结果：`coordinateSystem`、`geometry`、`uncertainRegion`、`unknownRegion`、`computationExtent`、`quality`、`stopReason`、`statistics`、`warnings` 和 `config`。顶层接口字段为 camelCase，算法统计与配置字段沿用 snake_case。几何显式标注 BD09LL，不应作为标准 WGS84 GeoJSON 直接导入其他地图。

预算或截止产生的部分结果、证据不足结果可正常完成；上游权限和配额异常通过停止原因与未知结果体现。几何重建异常及未捕获执行异常标记 `failed`，不给出成功几何。

| 状态码 | 含义 |
| --- | --- |
| 404 | 任务不存在、已过期或服务重启后丢失 |
| 409 | 服务忙、幂等参数冲突，或任务没有可读取的完成结果 |
| 422 | 请求参数不符合契约 |
| 503 | 真实步行配置缺失，或 QPS 不足以完成初始化 |

## 5. 可复制的安装与启动命令

本机验证环境为 Python 3.11.15、现有 Node/npm、Microsoft Edge。依赖使用 NumPy 2.4.6、Shapely 2.1.2、ContourPy 1.3.3、HTTPX 0.28.1、FastAPI 0.141.1、pytest 9.1.1，后端锁文件已合并算法数值依赖，`uv pip check` 通过。

从仓库根目录打开 PowerShell：

```powershell
New-Item -ItemType Directory -Force D:/CodexTemp,D:/CodexCaches | Out-Null
$env:TEMP = 'D:/CodexTemp'
$env:TMP = 'D:/CodexTemp'
$env:UV_CACHE_DIR = 'D:/CodexCaches/uv'
$env:PYTHONPYCACHEPREFIX = 'D:/CodexCaches/baidu-pycache'
$env:PYTHONUTF8 = '1'
$analysisPython = 'D:/CodexCaches/baidu-map-algorithm-venv/Scripts/python.exe'
if (-not (Test-Path $analysisPython)) { py -3.11 -m venv D:/CodexCaches/baidu-map-algorithm-venv }
uv pip install --python $analysisPython -r backend/requirements.lock.txt -e ./life-circle-algorithm
uv pip check --python $analysisPython

# 离线后端；不访问百度服务
$env:ANALYSIS_PROVIDER = 'synthetic'
& $analysisPython -m uvicorn app.main:app --app-dir backend --host 127.0.0.1 --port 8000 --workers 1 --no-access-log
```

新开终端，从仓库根目录启动前端：

```powershell
Set-Location life-circle-demo
$env:npm_config_cache = 'D:/CodexCaches/npm'
# 已有 node_modules 时跳过安装。本机验收复用了已有依赖。
if (-not (Test-Path node_modules)) {
  New-Item -ItemType Directory -Force D:/CodexCaches/isochrone-node-modules | Out-Null
  New-Item -ItemType Junction -Path node_modules -Target D:/CodexCaches/isochrone-node-modules | Out-Null
  npm install --ignore-scripts --no-audit --no-fund --package-lock=false
}
$env:VITE_ANALYSIS_MODE = 'api'
$env:VITE_API_BASE_URL = 'http://127.0.0.1:8000'
npm run dev
```

打开 `http://127.0.0.1:5173`。没有浏览器地图 AK 时可以直接输入坐标并查看结果摘要。浏览器 AK 通过本地 `.env.local` 配置；服务端 AK 只放后端环境或 `backend/.env`。本轮没有修改已有密钥文件。

切回原演示时使用 `$env:VITE_ANALYSIS_MODE='demo'` 后重启 Vite。下一阶段启用真实模式需设置后端 `ANALYSIS_PROVIDER=baidu`、有效服务端 AK 和已核实的 `ANALYSIS_QPS`；不提供猜测的真实 QPS 默认值。

## 7. 下一步：正式实验测试

1. **冻结实验版本和配置。** 记录最终提交、依赖锁、坐标系、算法参数、随机种子、预算、QPS、测试时间和实验机网络出口；选定真实社区及 BD09LL 中心。当前页面默认中心仅为选点起始位置，不能算已验证社区。
2. **做真实接口小样本核验。** 核实服务端 AK 的步行权限、IP 白名单、额度及实际 QPS；请求少量路线，检查 `steps_info=1`、秒数、路线选择、实际起终点与偏移标志。N02 的地点检索成功不能替代步行权限验证。
3. **核验真实地图渲染。** 用真实浏览器 SDK 检查中心坐标、孔洞、多分量、未知和不确定图层及缩放显示；离线覆盖物契约测试不能替代这一步。
4. **建立独立验证集和真实实验入口。** 当前 CLI 只执行合成实验。下一阶段补充真实 Provider 的实验编排与脱敏记录，固定统一范围、验证点集和测时来源，隔离采样缓存与参考真值。不得将同一次采样插值结果作为自身真值。
5. **执行预算比较与消融。** 在 200/400/800 预算下比较自适应、均匀网格、扇形基线，再比较关闭主动补测、关闭探索。记录每次实际调用、重试、失败、耗时、端点未核验比例、未知比例、IoU、漏纳/误纳、边界 P95、孔洞及分量变化；未知计入漏纳评估。
6. **形成正式实验报告。** 逐社区说明证据、误差、成本、拓扑和失败原因；对截断或不足以评估的结果明确标记，不预设自适应优于基线。真实实验完成后，再规划设施检索/统计和持久化接入。

本轮交付的是可进行后续实验的等时圈链路及离线验收证据，尚未形成真实路网精度或真实服务可用性的结论。
