## 评价口径

- 误纳率：错误判为可达／全部预测可达的有效共同参考点。
- 漏纳率：真实可达但预测不可达或 unknown／真实可达参考点。
- unknown：未知预测／有效共同参考点。
- 与任一算法采样坐标重合的参考点从三个方法共同评价集合统一排除，不补采，再记录覆盖门槛。
- 原始计数、无效原因、每点预测、每个点对的覆盖、调用和耗时一并保存。零分母为 null。
- 新边界抽样集独立报告，不与旧广域参考混合，不声称真实面积 IoU、边界 P95、拓扑准确率或普遍排名。

## 记录故障离线复核及修复

在这次运行中，执行助手使用 PowerShell 打开 ledger.json 读取进度，并持有 FileShare.ReadWrite | FileShare.Delete 句柄。独立 D 盘临时文件复现表明：本机 NTFS 上，持有该句柄时连续 4 次 os.replace 均报 errno 13／WinError 5，关闭句柄后写入立即恢复。该监控读取与事件 82 记录失败时间重合，是有复现证据的触发因素。原始运行未保存系统错误码，因此不把具体因果写成已完全证实，也不推定上一轮事件 761 必然由同一原因导致。

停止保护生效：事件 82 尚无 dispatchPerf，后续没有新的网络交接；原始账本最后成功保存 halted=ledger_write_failed。D 盘复核为健康 NTFS，剩余约 32.9 GB，未发现空间耗尽证据。

后续修复仅改实验工具：

1. ProgressTransport 每阶段首个发送和每 20 次发送输出脱敏进度。**运行中不得再打开 ledger.json 轮询**；等待进程输出，不持有账本读句柄。
2. BoundaryLedger 记录白名单数字 errno、winerror、事件 ID 和固定操作名，不保存异常文本、URL 或 AK；文件写入失败仍立即停发，不通过追加网络重试绕过保护。
3. 分开 coverage_passed 与阶段 passed。原始 result.json 同时出现覆盖 passed=true 和 status=failed；更正后的 audited-result.json 明确 coverage_passed=true、passed=false。
4. 新增纯离线 `--audit`，补充确认发送证据和未测时状态；JSON/CSV 指标一致，原始文件不改写。

上述修复先写失败测试后实现。最终完整回归 251 项通过；MockTransport 覆盖正常完整比较、覆盖不足、限流、算法异常和第 82 次本地写失败阻断。Windows 文件读句柄冲突另有真实文件系统离线回归。执行后未发送任何追加步行请求，未重新启动本轮。
