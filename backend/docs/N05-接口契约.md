# N05：v1 响应契约与前端调用

依赖 N04 的三态规则。N01尚未提供可核验的最终口径：按任务要求保留待确认字段。模型真源 `app/contracts.py`；四组响应在 `mocks/`；JSON Schema 与 OpenAPI 快照在本目录。执行 `python -m tools.export_contract` 同步样例、Schema、OpenAPI及前端 `src/api-contract.ts`，不要单独手改生成文件。

## 路由与状态

| 请求 | 用途 | HTTP |
| --- | --- | --- |
| GET `/api/v1/analysis/mock/complete` | 完成场景：合成三类设施、完整数据 | 200 |
| GET `/api/v1/analysis/mock/partial` | 部分场景：保留药店，其他类别未知 | 200 |
| GET `/api/v1/analysis/mock/failed` | 业务失败样例；读取样例本身成功 | 200 |
| GET `/api/v1/analysis/mock/empty` | 查询完成、设施零条；评估点集为空 | 200 |
| POST `/api/v1/analysis/synthetic` | 实际执行合成算法 | 200 |
| 字段、坐标或枚举错误 | 同一响应模型，status=failed | 422 |
| 未处理的执行异常 | 固定脱敏错误，同一响应模型 | 500 |

状态判断顺序：没有可信业务结果为 failed；仍有未知、未运行模块或未确认规则为 partial；所有所需模块已完成且设施结果为零为 empty；其余完整结果为 complete。`empty` 是本契约的**设施查询零结果**，不代表等时圈为空，更不代表整片社区是盲区。四组 Mock 的 complete/empty 使用显式虚构规则，只用于演示完成状态，不代表团队已确认这些规则。

`algorithm.quality` 与总状态不同：本次 synthetic 的 usable/partial 都映射 partial（设施/盲区/报告未运行）；insufficient 映射 failed 并保留未知区与统计。**insufficient 绝不映射 empty**。即使算法局部可用，也不宣称整个体检完成。将来其他模块接入后应按总状态优先级汇总。

## 字段含义与需求追溯

所有顶层和 data 字段在四种响应中始终存在；失败也保留 data 对象及三类状态。没有第二个 success 布尔值：HTTP是否成功用 HTTP 状态，业务结果用 status，避免矛盾。

| 字段 | 含义 | 需求 |
| --- | --- | --- |
| schema_version / analysis_id / generated_at | 结构版本、同一次分析标识、UTC生成时间 | FR-01、FR-08 |
| origin | 命名 lng/lat，原始所选位置；无有效请求时null | FR-01 |
| coordinate_system / coordinate_order / units | BD09LL、经度在前、m/s/m2；每个几何也有坐标系 | FR-01～FR-08 |
| source / data_updated_at | mock/synthetic/system，数据更新时间未知为null；generated_at不替代更新时间 | FR-08 |
| rules | 900秒、边界实现状态、独立距离规则、待确认范围与分类策略 | FR-02、FR-06 |
| data.geometry / uncertain_region / unknown_region / computation_extent | 等时圈、需谨慎区域、未知区域、计算范围（相互可重叠） | FR-02 |
| data.facilities | 设施id/分类/真实格式坐标/圈内三态；Mock设施均虚构 | FR-03、FR-04 |
| data.categories | market/pharmacy/school，查询状态、圈内数量、点集服务状态 | FR-05 |
| data.blind_points / blind_region | 逐类点位和依据、灰区几何；未执行为null | FR-06、FR-07 |
| data.report | 当前分析报告摘要；未执行为null，不生成无依据评分 | FR-08 |
| algorithm / algorithm_version | 原始算法证据对象及提交版本；供核查，页面依赖规范化data | FR-02、FR-08 |
| warnings / errors | 稳定code、可读message、scope、severity；pending用红色和文字提示 | 第9节 |

几何为类 GeoJSON Polygon/MultiPolygon，可有孔洞、多分量，但坐标为 **BD09LL，不是标准 WGS84 GeoJSON**。严禁直接用 WGS84图层解释。面积统计在算法局部米制投影中计算，不对经纬度多边形面积直接标m2。`algorithm` 保留上游 camelCase 原件用于追溯；页面使用 snake_case 的规范化 data。

null = 未执行/未知/无可信结果，结合类别状态与warning识别原因；0 = 已查询并已计数为零；[] = 该集合已处理且无项目；空几何 = `{"type":"MultiPolygon","coordinates":[],"coordinate_system":"bd09ll"}`。缺字段不替代null。盲区点集为空时 `service_status=unknown` 表示不适用/无评估点，不凭零设施生成灰区。

## 前端使用与迁移边界

```typescript
import { createAnalysisClient } from './api-client';
const api = createAnalysisClient('http://127.0.0.1:8000');
const sample = await api.mock('partial');
const result = await api.synthetic({
  origin: { lng: 116.4, lat: 39.9 }, coordinate_system: 'bd09ll', scenario: 'plane'
});
```

`AnalysisHttpError` 携带HTTP状态与同结构错误响应；200+failed仍需按status处理。网络断开/非JSON响应作为请求错误处理。AbortSignal可停止客户端等待，但不保证服务器任务取消。展示仅采用当前analysis_id与原点一致的结果，中心变更后禁止拼接旧报告。

旧 `types.ts` / `service.ts` 面向画布Point{x,y}，没有地理地图适配，不直接将本响应强制转换为旧 AnalysisResult。本次提供独立API客户端、自动生成类型和共享Mock测试；切换正式地图及异步任务流程属于后续联调任务。默认前端界面保持原Demo行为。

## 简短分支规则

1. 从团队 `upstream/main` 新建 `feat/nXX-short-topic`；一支聚焦一个可评审改动，同一契约依赖的N04/N05允许一起提交。
2. 提交前同步主分支，保留他人本地改动；不强推共享分支、不直接改受保护main。
3. 契约字段变动先改Pydantic模型，再重建四组Mock/Schema/前端类型，后端及前端共享样例自测。
4. PR写清场景前后行为、待确认项、测试结果；前后端各一人核对字段/坐标/null语义，再按仓库现有Review与CI规则合并。
5. 密钥只在服务端本地配置，不提交env、日志、缓存或真实调用URL；Mock不读取真实账号。

本次侧栏GPT讨论采纳：业务/算法状态分离、版本追溯、HTTP错误契约、null与空集区分。未采用其“insufficient可映射empty”的示例，因为这会把证据不足误标为空结果。团队人工口径确认仍需真实负责人完成。
