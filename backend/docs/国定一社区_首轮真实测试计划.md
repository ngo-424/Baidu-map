HTTP 发送前预留预算并持久化。总账固定在 `D:/CodexOutputs/guodingyi-live-smoke/ledger.json`，不因更换运行编号或进程重启而清空；每个运行编号的配置、状态、结果、截图另存子目录。崩溃后未确认是否发送的预留也计入预算。进程锁阻止多实例共同消费额度。

## 3. 用例与停止条件

### T01 步行冒烟

按固定顺序查询局部米制东、西、南、北各 200 米、600 米的 8 个位置，经现有投影转换并归一化为六位小数，不调用地理编码。

核验 HTTP/百度状态、有效秒数、多路线选择、BD09LL 请求及返回坐标、`steps_info=1`、实际端点和 50 米偏移规则。端点缺失记未核验，未知不解释为不可达。

至少获得一条完整端点且偏移不超过 50 米的有效路线，才允许进入后续阶段。权限/IP、配额、参数错误立即停止；持续限流或连续故障达到停止条件也停止。本阶段失败后不自动重做整组冒烟。

### T02 运行中取消

通过现有任务 API 创建测试任务，观察到第一次发送预留后立即调用取消。传输层最多 4 次调用，取消生效后禁止后续发送。在途请求单独记录；任务必须最终 cancelled、无完成结果，迟到返回不能改写终态，退出后释放运行名额。

### T03 200 次完整闭环

在真实前端填写固定中心并选择 200 次预算，仅创建一次完整分析。核验创建、每秒状态轮询、结果读取、`baidu_walking` 来源、中心与 BD09LL、多分量/孔洞、未知和不确定图层、计算范围、真实停止原因及质量提示。

partial 可作为链路证据，但必须解释原因；insufficient 或执行失败不能记为成功生成等时圈。null 和有效空几何分别展示，未知区域不能被填入可达区，设施统计保持尚未接入。

### T04 真实地图

检查桌面及移动端、选点、缩放、图层和摘要，保存截图。实际结果无孔洞或多个分量时，在真实 SDK 上叠加独立且明确标记的固定夹具，专项验证镂空和多个分量；不算社区采样，不发送步行请求。

### 统一停止规则

预算触顶、鉴权失败、持续故障、明显坐标偏差或凭据进入产物风险出现后，停止后续真实请求。完整分析失败不追加第二次 200 请求任务。代码修复先跑离线回归；不扩大预算。未执行用例注明原因，不写成通过。

## 5. 实施入口与执行命令

新增 `backend/tools/live_smoke.py`，在现有 FastAPI 外围增加本轮专用测试控制，不修改业务接口。测试控制端口只监听 `127.0.0.1:8019`。

| 测试控制接口 | 用途 |
| --- | --- |
| GET /live/map | 真实 SDK 中心核对及独立几何夹具 |
| GET /live/status | 脱敏阶段状态、累计预算与停止原因 |
| POST /live/confirm-map | 人工核对地图后记录确认，不可提前调用 |
| POST /live/smoke | 执行一次 T01，拒绝重复启动 |
| POST /live/finish-cancel | T02 任务退出后检查终态和发送账本 |
| GET /live/export | 保存当前任务状态及结果 |

在仓库根目录运行；使用已安装的环境，无需再次下载依赖：

```powershell
$analysisPython = 'D:/CodexCaches/baidu-map-algorithm-venv/Scripts/python.exe'
$env:PYTHONPYCACHEPREFIX = 'D:/CodexCaches/baidu-pycache'
$env:PYTHONPATH = (Resolve-Path backend).Path
$runId = Get-Date -Format 'yyyyMMdd-HHmmss'
& $analysisPython -m tools.live_smoke --output D:/CodexOutputs/guodingyi-live-smoke --run-id $runId --port 8019
```
